# Tesseract 知識庫 Skill

## 觸發條件

當專案根目錄存在 `tesseract/` 資料夾（symlink），此 skill 自動生效。

---

## 工作前：載入知識庫

1. 讀取 `tesseract/index.md`，了解此 domain 有哪些知識檔案（`## Files` 清單）
2. 讀取與當前任務相關的知識檔案（不需全部讀，按需讀取）
3. 一句話告知使用者已載入哪個 domain

---

## 知識庫結構

```
tesseract/           ← symlink 到 iCloud/Tesseract/<domain>/
  index.md           ← 索引：domain 說明 + Files 清單 + Changelog
  <topic>.md         ← 知識檔：一個主題一個檔案
  assets/            ← 圖片、影片等靜態資源
```

**`index.md` 只是索引**，不存放知識內容。
**知識存在各自的 `<topic>.md` 檔案中。**

---

## 何時強化知識庫（主動，不等使用者）

以下情況發生時立即更新，不需使用者要求：

1. **設計或架構決策**：選定技術方向、排除某方案、確認設計模式
2. **問題解決**：找到 bug 根因、確認 workaround、理解系統行為
3. **使用者偏好**：使用者糾正做法、明確表達喜好或不喜好
4. **重要洞見**：對話中途出現值得保留的知識

更新後告知使用者「已記錄到知識庫」（一句話），不中斷主要工作。

---

## 如何強化知識庫

### 步驟 1：找到對應的知識檔
- 查看 `index.md` 的 `## Files` 清單
- 找到主題相符的 `.md` 檔案，讀取後更新
- 若找不到相符檔案，建立新的 `<topic>.md`

### 步驟 2：更新知識檔
- 在正確的章節下新增或精煉知識
- 使用 `#tag` 標記主題（放在檔案標題下方）
- 使用 `[[檔名]]` 連結同 domain 的其他知識檔
- 使用 `[[domain/檔名]]` 或 `[[domain]]` 連結其他 domain
- **不刪除**既有內容；若有修正，在同一條目加「修正：」

### 步驟 3：若新增了知識檔，更新 `index.md`
在 `## Files` 加入一行：
```
- [[topic-name]] — 一句話說明 #tag
```

### 步驟 4：在 `index.md` 的 `## Changelog` append 一行
```
- YYYY-MM-DD: 說明更新了什麼（AI）
```

---

## 使用者觸發時更新

使用者說「完成」、「謝謝」、「更新知識庫」、「記錄到 Tesseract」時也執行上述步驟。

---

## 連結規範

| 場景 | 語法 | 範例 |
|------|------|------|
| 同 domain 內的檔案 | `[[topic-name]]` | `[[budget]]` |
| 跨 domain | `[[domain]]` 或 `[[domain/topic]]` | `[[honeymoon]]`、`[[honeymoon/budget]]` |
| 主題標籤 | `#tag`（放標題下方） | `#架構決策` |

---

## 禁止事項

- 不把知識內容寫進 `index.md`（它只是索引）
- 不把程式碼存入知識庫（只存知識、洞見、決策、偏好）
- 不刪除 Changelog 既有記錄
- 不在沒有實質新知識的情況下更新（避免雜訊）

---

## 跨 Domain 處理

若知識超出當前 domain 範疇：
1. 先記在當前 domain，標記「可能屬於其他 domain」
2. 提醒使用者：`tesseract new-domain <建議名稱>`
