# Tesseract 知識庫 Skill

## 觸發條件

當你在某個專案中工作，並且該專案根目錄存在 `tesseract/` 資料夾（symlink），此 skill 自動生效。

---

## 工作前：讀取知識庫

1. 讀取 `tesseract/index.md`
   - 若 context 已很緊張，且存在 `tesseract/summary.md`，改讀 summary
2. 簡短告知使用者已載入哪個 domain 的知識（一句話即可）

---

## 工作中：運用知識

- 利用知識庫中的 `## User Preferences` 主動適應使用者的工作風格
- 利用 `## Knowledge` 中的架構知識做出一致的技術決策
- 若觀察到與知識庫矛盾的情況，指出並確認

---

## 工作結束時：更新知識庫

當以下任一情況發生時執行更新：
- 使用者說「完成」、「謝謝」、「結束」
- 使用者明確說「更新知識庫」或「記錄到 Tesseract」
- 對話達到自然結束點

更新步驟（依序）：

### 1. 更新 `## Knowledge`
- 新增此次工作中發現的重要洞見、架構決策、技術細節
- 精煉（refine）已存在但不夠清楚的知識點
- **不刪除**任何既有內容；若有衝突，在同一條目下加入「修正」

### 2. 更新 `## User Preferences`（僅在有新觀察時）
- 記錄本次對話中觀察到的使用者習慣或偏好
- 只記錄**確認觀察到**的，不臆測

### 3. 更新 `## Open Questions`（僅在有新問題時）
- 新增此次工作中出現的、尚未解決的問題
- 若某個問題已解決，從此節移除並在 Knowledge 記錄答案

### 4. Append `## Changelog`
在 Changelog **最下方**新增一行：
```
- YYYY-MM-DD: <本次更新的簡短說明>（AI）
```

---

## 禁止事項

- 不把程式碼存入知識庫（只存知識、洞見、決策、偏好）
- 不刪除 Changelog 的既有記錄
- 不修改 Changelog 過去的條目
- 不在沒有實質新知識的情況下更新（避免雜訊）

---

## 人工介入提示

若使用者在 IDE 中直接修改了 `tesseract/index.md`（而非透過 AI），在下次工作時你會看到不同版本的內容。這是正常的——使用者有權直接修正 AI 寫入的知識。直接基於最新版本繼續工作即可。

---

## 跨 Domain 處理

若此次工作涉及超出當前 domain 範疇的重要知識：
1. 正常將其寫入當前 domain 的 `## Knowledge`，並標記「可能屬於其他 domain」
2. 提醒使用者：「這部分知識可能適合建立新 domain：tesseract new-domain <建議名稱>」
