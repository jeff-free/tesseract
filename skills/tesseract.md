# Tesseract 知識庫 Skill

## 觸發條件

當你在某個專案中工作，並且該專案根目錄存在 `tesseract/` 資料夾（symlink），此 skill 自動生效。

---

## 工作前：讀取知識庫

1. 讀取 `tesseract/index.md`
   - 若 context 已很緊張，且存在 `tesseract/summary.md`，改讀 summary
2. 簡短告知使用者已載入哪個 domain 的知識（一句話即可）

---

## 工作中：運用知識

- 利用 `## User Preferences` 主動適應使用者的工作風格
- 利用 `## Knowledge` 做出一致的技術決策
- 若觀察到與知識庫矛盾的情況，指出並確認
- 注意 `[[domain-name]]` 連結，必要時提示使用者讀取相關 domain

---

## 何時主動強化知識庫（不等使用者說）

以下情況發生時，**主動**更新知識庫，不需等使用者要求：

1. **做出架構或設計決策**：選定某個技術方向、設計模式、或排除某個方案
2. **解決了一個問題**：找到 bug 根因、確認 workaround 有效、理解了某個系統行為
3. **發現使用者明確的偏好**：使用者糾正了你的做法、明確表達了喜好或不喜好
4. **對話中途出現重要洞見**：不需等到對話結束，立即記錄

**做法**：直接更新 `tesseract/index.md`，然後告知使用者「已記錄到知識庫」（一句話）。

---

## 使用者觸發時強化知識庫

使用者說以下詞語時也執行更新：
- 「完成」、「謝謝」、「結束」
- 「更新知識庫」、「記錄到 Tesseract」

---

## 更新步驟（依序）

### 1. 更新 `## Knowledge`
- 新增此次工作中發現的重要洞見、架構決策、技術細節
- 精煉（refine）已存在但不夠清楚的知識點
- **不刪除**任何既有內容；若有衝突，在同一條目下加入「修正：」
- 使用 `#tag` 標記主題，例如 `#架構決策`、`#使用者偏好`

### 2. 更新 `## User Preferences`（僅在有新觀察時）
- 記錄本次對話中觀察到的使用者習慣或偏好
- 只記錄**確認觀察到**的，不臆測

### 3. 更新 `## Open Questions`（僅在有新問題時）
- 新增尚未解決的問題
- 若某個問題已解決，從此節移除並在 Knowledge 記錄答案

### 4. 更新 `## Related Domains`（僅在有跨 domain 關聯時）
- 使用 `[[domain-name]] — 關聯說明` 格式
- 若判斷某個知識更適合放在其他 domain，提醒使用者

### 5. Append `## Changelog`
在 Changelog **最下方**新增一行：
```
- YYYY-MM-DD: <本次更新的簡短說明>（AI）
```

---

## 連結規範

**跨 domain 連結**：使用 `[[domain-name]]` wiki-link 格式
- 放在 `## Related Domains` 節，或在 Knowledge 內文中行內使用
- 範例：`此決策與 [[product]] 的設計方向一致`

**主題標籤**：使用 `#tag` 行內標記
- 放在知識條目結尾
- 範例：`使用 RSpec one-liner 語法 #測試偏好`

---

## 禁止事項

- 不把程式碼存入知識庫（只存知識、洞見、決策、偏好）
- 不刪除 Changelog 的既有記錄
- 不修改 Changelog 過去的條目
- 不在沒有實質新知識的情況下更新（避免雜訊）

---

## 人工介入

若使用者在 IDE 中直接修改了 `tesseract/index.md`，下次工作時直接基於最新版本繼續。使用者有權修正 AI 寫入的知識。

---

## 跨 Domain 處理

若此次工作涉及超出當前 domain 範疇的重要知識：
1. 在當前 `## Knowledge` 中記錄，標記「可能屬於其他 domain」
2. 提醒使用者：`tesseract new-domain <建議名稱>`
